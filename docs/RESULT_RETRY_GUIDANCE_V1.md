# 結果取得の理由表示・個別再確認 v1

検証ダッシュボードの「レース後結果を自動取得」に、未取得レースの折りたたみ一覧を追加する。レースID、JRA/NAR、取得理由、次に行う操作、最終確認、試行回数、次回確認日時（JST）、上限到達を表示する。最初は20件、必要なら20件ずつ追加表示する。

「このレースだけ再確認」は選んだ1レースのみを既存の結果取得経路で確認する。他の待機レースの一括再送やクラウド保留の解除をしない。レース識別情報、取得済み結果、停止状態、発走時刻+10分、前回確認から1分、他の処理中を検査する。上限到達後も明示的に1回確認できるが、失敗しても自動再試行は再開せず、試行履歴と回数を保持する。

自動再試行の上限は6回、既存の5/5/10/15/30分の待ち時間と順次取得を維持する。ページを開き直すだけで上限到達を解除しない。手動で成功した場合だけ既存の結果保存・参考検証へ進む。途中でレースが削除・変更された場合は既存のcommit guardで破棄する。

手動結果取得も、未掲載、通信失敗、タイムアウト、アクセス制限、応答不正、設定OFF、原因不明を日本語で説明する。生のサーバーメッセージは主表示へ出さない。既存保存結果がある更新失敗は保持を明示する。JRAのHTTP応答のerrorフィールドにある公式エラーコードも保持し、未掲載を通信エラーへ混同しない。JRA選択変更後の失敗応答は新しいレース表示へ反映しない。

## 検証範囲

- 理由の分類、JRA/NAR、停止・取得済み・発走前・識別不一致・時間間隔、上限、個別選択、同時操作、遅延応答、HTMLエスケープを検証。
- 実ブラウザで320/390/430pxを確認し、実際のクリックが1レースだけを取得し、確認中・1分間隔の無効化と上限表示を保つことを確認。
- Original EARLY、Prediction/Market/FINAL、固定Signal、既存の結果照合条件は緩めない。正式EARLY判定の昇格は行わない。
- Worker、D1 schema/migrations、cron、workflowは変更しない。新たな結果取得は利用者が個別ボタンを押した場合のみ。既存の通常保存・クラウド同期経路はそのまま使う。
- ローカル結果とGitHub結果は区別する。PR最終確認では全件テストが必要。
