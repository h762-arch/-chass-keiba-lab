# Phase81: NAR multi-angle history interpretation v1

## Scope

This is a read-only, offline research explanation layer attached to the existing
NAR evidence consumer. It interprets history already projected from Drive, rather
than fetching Drive from production. No probability weight, ranking, ability
mark, Original Signal, Freeze, DB write, deployment, or runtime flag is changed.
Formal EARLY remains HOLD; Production Activation remains NO-GO.

The existing probability/mark calculation remains index-led. This patch does NOT
claim that the probability model now consumes historical course, distance,
last3F, or passage features. Their predictive coefficients require separate
forward validation, versioned model changes, and calibration evidence.

## Data and computation

`buildNarHistoryInterpretation({race, horse})` accepts the Phase77 projected race
and horse contract, with at most ten strictly prior, valid-date historical runs.
Current/future history, malformed dates, unsupported target surface, and oversized
history fail closed. Dirt/turf/unknown histories are kept distinct. Missing or
annotated values are not guessed, stripped to zero, or turned into ability scores.

| Dimension | Interpretation and boundary |
| --- | --- |
| Recent form | Most recent five dirt observations, valid finish count, wins/top3, median finish and finish fraction |
| Same course | Exact course-name match, observation/result counts and references |
| Same distance | Exact distance only, without arbitrary near-distance conversion |
| Exact context | Both exact course and exact distance |
| Clock | Exact-context seconds grouped by historical going; no distance or going correction |
| Last3F | Exact-context observations grouped by historical going; no pace adjustment |
| Position | First/last retained passage and finish deltas; NOT certified first-corner position or a lead/retention/closing rate |

Finish fraction is `(finish - 1) / (fieldSize - 1)` only when fieldSize is an
integer greater than one and finish is an integer within that field. It is a
descriptive ordinal fraction, NOT an ability score or probability. Samples with
invalid/missing denominators do not count as valid results.

Position requires at least two retained positive integer passages within the
field and a valid finish. First-to-last gain is `firstRecorded - lastRecorded`;
last-to-finish gain is `lastRecorded - finish`. These are observations, not an
inferred race-flow scenario. The adapter can omit missing passage columns, so
first retained passage must never be labelled the first corner or early pace.

Clock and closing medians are calculated separately for 良/稍重/重/不良/UNKNOWN.
An unknown current going never selects a convenient past going. Exact course
and distance do not certify pace, class, course configuration, weather, or surface
equivalence. A single observation is recorded but never generalized into a
confident future prediction. No new TIME forecast is generated by this module.

Every dimension carries the projected history index, date, course and distance
for attribution. These indices refer to `pastRuns`, not original Drive row numbers;
the adapter audit and snapshot evidence retain the original row association.

## Counter-evidence and incomplete reasoning

Structured counter-evidence includes missing dirt/same-course/exact-distance
history, absent exact-context history, unknown current going, absent current-going
clock/last3F reference, missing passage/result samples, invalid finish denominators,
and single-observation limitations. These are research limitations, not automatic
warning/diamond tags or forecast failure decisions.

Unassessed factors explicitly include race-flow fit, class equivalence, current
ability, Pressure, pedigree, jockey intent, and market value. Historical result
rates or last3F cannot stand in for these. This is not a complete devil's-advocate
review or automatic Final5 decision; it provides attributable material for that
review. No index-only mark is represented as multi-angle confirmed.

User signal rules remain unchanged: scenario before signal, concrete support and
appropriate pre-race market evaluation, warning/mark exclusion, and immutable
Original Signal. This module generates neither diamonds nor warnings.

## Consumer propagation audit

Both separate pre-off and retrospective consumer entrypoints return additional
`historyInterpretation` arrays inside before/after research output. Existing
snapshot schemas and Phase80 timing/eligibility separation remain unchanged.

Family ablation tracks `HISTORY_INTERPRETATION` separately from
`PROBABILITY_OR_ABILITY_MARK` and `TIME_RESEARCH`. `interpretationUsed: true`
means that explanation changed; it alone NEVER grants `decisionUsed: true`
or a DECISION_USED stage. Explanation-only traces report
`EXPLANATION_ONLY_NOT_PREDICTION_DRIVER`. If prior history also changes the
existing TIME research output, the existing TIME-only decision-use semantics
remain and do not imply probability influence.

The consumer returns `predictionChanged`, `timeChanged`, and
`interpretationChanged` separately. Aggregate `changed`/outputHash now include
explanation output; they must not be used alone as evidence of forecast change.
`historyInterpretationStatus` is `RESEARCH_EXPLANATION_NOT_PREDICTION_DRIVER`.
