# 同期保留の本文差分診断 v1

同期保留の詳細を開き「保留の差分を確認（送信なし）」を押す。最大100件を1件ずつ照合し、診断日時と差分項目を表示する。予想・市場・確定シグナル・FINAL・結果・検証フラグ・同期保留・送信待ちは変更しない。クラウドへの書き込みはない。診断結果だけを端末に保存し、研究バックアップの syncDiagnostics.holdAudit に含める。再読み込みやバックアップ読み込みで診断操作を再実行しない。

## 判定

判定の優先順は、識別情報の不備、元予想・市場・FINAL、結果、レース情報、参考検証・処理状態のみ、本文・状態一致。差分項目自体はすべて保持する。「参考検証・処理状態のみ」は安全な自動採用を意味しない。本文・状態一致でもこの操作では保留を解除しない。元予想の印、💎、⚠️は凍結された比較対象であり書き換えない。

GET /api/db/hold-audit?raceId=...&modelVersion=... はモデルまで一致する1行をバインド変数付き SELECT で読む。スキーマ作成やメタデータ更新をしない。6つのJSON本文は合計256KiBまで。存在しない行、壊れたJSON、過大な本文、DB障害は明示的なエラーにする。race_json 内の結果取得状態・直前評価・取消検証・照合情報は比較用に分離し、JSONのキー順は無視する。欠落と null は比較用に正規化する。端末の状態は既存の queueCloudStatus で求め、クラウド状態は保存された status を使う。

操作中の二重実行と同期送信を防ぎ、1件20秒でタイムアウトする。通信途絶では完了済みの診断を残して停止する。個別のHTTP・本文エラーは未完了として後続を続ける。診断中に端末が編集されたレコードは見送る。保存失敗を成功として表示しない。保存する診断は分類・差分項目名・識別子・日時のみで、クラウドのJSON本文は保存しない。

## 実測の背景と適用範囲

2026-10-19の端末バックアップと本番manifestでは、結果補完済み40件の元予想・結果・FINAL・直前評価の照合値が一致した。39件は状態・raceFingerprint・validationFingerprintに差分があり、大井2026-09-14 12Rの1件は市場にも差分があった。これは既存照合値による調査で、今回の本文診断は未デプロイ。実際の差分診断と採用可否はデプロイ後に確認する。

全体の残保留58件には原本競合や識別情報不足が含まれる。今回のパッチは診断のみで、元データの自動修復・保留解除・本番公開判定を行わない。Formal KPI HOLD / Probability MODEL_HOLD / Production NO-GOを維持する。
