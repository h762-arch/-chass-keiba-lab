# Phase78: NAR Prediction Evidence Consumer v1

Research-only Node composition. Production Activation NO-GO; formal EARLY HOLD.

## What is connected

Phase77 immutable Prediction Evidence Snapshots can now be compared through the
actual existing NAR app `transform` entrypoint and the existing NAR TIME theory.
The consumer loads repository app.js in a VM with __CHASS_TEST__ enabled.
No fetch, DOM, timer or DB implementation is supplied; local storage writes throw.
This is an isolated research harness, not a browser or Worker runtime dependency.
app.js, worker.js, model weights, routes and deployment flags are unchanged.
Results retain app version and app source hash with snapshot/run/model identity.

The consumer requires exact baseline race/run/model, active horse key/number
association, at least two active horses and a supported NAR dirt course. Band
racing and NAR turf are not supported. Snapshot hash is verified before execution.
Source authentication, trusted timing and identity remain caller declarations
from Phase77, not a new formal certification.

## Input mapping and influence

| Family | Actual consumption | Trace scope |
| --- | --- | --- |
| Raw index | PeakIndex -> timeIndex; Avg5Index -> fiveRaceAvgIndex; DistanceIndex -> distanceIndex; CourseIndex -> courseIndex; complete prior 3/2/1 -> chronological recentIndex | Existing probability/ability-mark calculation |
| Carried weight | WeightCarried -> assignedWeight | Existing probability/ability-mark calculation |
| History | Same-surface runs -> existing buildNarTimeTheory | TIME_RESEARCH only |
| Pressure, position, pedigree coverage, signal notes | Inspected, no model mapping | Explicitly unused |

Raw index propagation requires an explicit research-only scale association:
indexPolicy.status=APPROVED_RESEARCH, scale=NAR_APP_RAW_INDEX, exact snapshotHash,
runId, modelVersion and nonempty evidenceRef. It is a caller declaration, not
formal policy approval. Raw Drive indices are not assumed to be worker-derived
history scores. No automatic conversion to 0-100 or new weights is added.
The existing app normalizes its mapped index features relative to the field.
Missing fields do not erase existing baseline evidence. A partial recent series
is not fabricated or padded. At least two finite primary index fields per active
horse are required for probability/ability-mark calculation; otherwise those
outputs remain null/empty. Weight alone cannot generate probabilities.

The existing app computes four ability marks (◎○▲△); this patch does not add ☆
or a new Final5 decision. Existing probabilities remain uncalibrated. Current
market, supplied probability overrides, old marks and result fields are excluded
by explicit projection. No diamond/warning is generated. User signal rules v1.0
and Original Signal immutability remain authoritative.

Per-family ablation compares the actual consumer output. DECISION_USED requires
an observable difference, and affectedOutputs separately names
PROBABILITY_OR_ABILITY_MARK and TIME_RESEARCH. A TIME-only change never claims
probability influence. This is operational influence, not evidence of better
accuracy, calibrated probability, formal EARLY or profitability. Baseline and
Snapshot are not mutated; freezeMutation and signalMutation remain NONE.

## Current real-data boundary

Canonical Drive metadata and Phase77 sentinel reads establish the unified schema.
Bounded searches of CHASS_UNIFIED_RUNNER_EARLY A1:F500 and the identity
column A1:A5000 for NAR found no matching rows on 2026-10-08.
NAR_指数マスター A1:AA3 and NAR_近10走マスター A1:AI3 were then read.
They contain NAR data: sampled index rows are 20260907_KAWASAKI_01; sampled
history rows are 20260914_OOI_12. These different race IDs cannot be joined
merely by horse number. Source race association and lineage identity require
explicit mapping; canonical NAR prediction inputs are not fabricated.
This patch does not synthesize real identities, source timing or scale approvals.
Synthetic fixtures demonstrate actual existing model execution and changed
outputs only. Real-data Snapshot-to-NAR prediction validation remains unachieved.
