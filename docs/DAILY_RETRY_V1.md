# 日次画像の研究用再試行

「失敗分を再試行（研究用）」は日本時間当日の完了済みHOLD/PARTIALを対象に、別IDのジョブを予約する。次の既存5分cronが新しい画像取得・Vision OCR・Producer検証・D1保存と読戻しを行う。HTTPリクエスト中に長時間OCRを行わない。

- 同じ接続キーまたは30日Cookie、同一OriginのPOSTが必要。URLにキーを入れない。
- 一日最大8回、同時に1回。元の9時ジョブ・画像入力・結果を削除または上書きしない。
- 画像は別の `IMAGE_DAILY_RETRY_V1:日付:UUID`、分析は `DAILY_RETRY_V1:日付:UUID` に保存する。実際の取得・Freeze・分析時刻を使い、発走時刻の検証を維持する。
- 再試行は画像フォルダを再取得する研究用途。登録済みDriveフィードの再取込や正式EARLY/Signalの更新を行わない。Driveへの出力は行わない。
- 表示APIは最新の研究用再試行と元の9時ステータスを返す。過去の試行はD1に残る。
- 中断されたPROCESSING/RUNNINGは自動的に再取得しない。二重処理を防ぐため、保存状態を調査する。前日の未処理予約を翌日に遡って処理しない。
- DB変更なし。既存0016/0018テーブルを使う。デプロイ後にアプリで予約し、定期実行後に保存済み分析を表示する。

Wranglerには今回選択済みの設定（分析ON・画像ON・Drive出力OFF）を保持する。Google Visionは既存キーを使うため、再試行ごとに読取APIの利用が発生する。成功は実際の本番OCRと読戻し結果で確認する。
